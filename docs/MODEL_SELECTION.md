# モデル選択・導入機能（利用者向け変更概要）

対象ブランチ: `feat/model-selection-setup`（起点 `3457912`）。受入確認済みコード HEAD は `2ef63f4bc8f2ec6030ca3307739eee6eda7a63b7` です。検証と利用者確認の記録は [VERIFICATION.md](VERIFICATION.md)（2026-11-16 の節）、制約は [PUBLIC_LIMITATIONS.md](PUBLIC_LIMITATIONS.md) を参照してください。

> [!IMPORTANT]
> **Web UI のモデル選択と、`llama-server` の起動・切替は別の操作です。**
> Web UI で「使用モデル」を選んでも、すでに起動している `llama-server` が自動で入れ替わったり再起動したりすることはありません。選択モデルと稼働中サーバーが一致しない場合は、翻訳開始が拒否されます（下記「現在の接続・一致確認」）。
> 今回の実機確認は、別ポートで稼働していた 0.8B（`:8001`）と 2B（`:8000`）の `llama-server` に、それぞれ接続して行ったものです。**同一ランチャーからのモデル自動切替・再起動を最後まで通して確認したものではありません。**

## 1. 今回できるようになったこと

| 機能 | 内容 |
|---|---|
| カタログからのモデル選択 | 同梱のモデルカタログ（`backend/model_catalog.json`）から導入するモデルを選べます（PLaMo 3 Translate 0.8B / 2B / 8B、いずれも Q4_K_M）。初回セットアップ画面と、画面1・画面4のモデル選択パネルで利用できます。 |
| ライセンス確認・同意を伴うダウンロード | モデルごとのライセンス告知を表示し、同意したうえで公式配布元（Hugging Face、カタログに固定されたリビジョン）から取得します。進捗表示・キャンセルに対応します。 |
| 手元の GGUF の reference 登録 | すでにダウンロード済みの GGUF を、コピー・移動・再ダウンロードせず、元の場所を参照する形で登録できます（既定）。 |
| 必要に応じた copy 登録 | 希望する場合は、管理フォルダーへコピーして登録することもできます。 |
| 検証 | 登録時に SHA-256、GGUF 形式、バックエンド互換性を検証します。カタログにない GGUF、`plamo3` 以外のアーキテクチャ、分割 GGUF、サイズやハッシュが一致しないファイルは登録できません。 |
| 不一致ガード | 選択中のモデルと、稼働中の `llama-server` が読み込んでいるモデルを比較します。不一致、または選択モデルが利用不可の場合、ジョブ開始時にエラー（`ModelMismatchConflict`）で拒否します。翻訳ジョブ実行中は、使用中モデルの登録解除も拒否されます。 |
| モデル別の記録 | 翻訳キャッシュのキーにモデル ID・モデル名・ハッシュを含めるため、別モデルの訳文を取り違えて再利用しません。ジョブの `report.json` の実行履歴（`execution_provenance`）に、使用したモデル ID・ファイル名・SHA-256・接続先などを記録します。 |
| 検証履歴と現在の接続状態の分離表示 | 4 段階の検証履歴（下記）と、現在の接続・一致状態（`server_match`）を別の項目として表示します。 |
| Screen 2 の最新同期・未保存編集保護 | 画面2に戻ったときに最新のブロック一覧・分割指定を取得します。取得に失敗した場合は古い状態を最新として扱わず、未保存の編集は同期で無断上書きしません。 |
| 実設定に対応した接続先表示 | 画面1の推論エンジンに、設定済みの `llama-server` 接続先を表示します（未取得時は「設定済みllama-server」）。固定の `:8000` 表示ではありません。 |
| 行末ハイフン正規化 | 行末の分割ハイフン（`compo- nent` など）を、位置・幾何情報を使って保守的に結合した文を LLM 入力にします。原文・座標・原 PDF は変更しません（`TranslationJobConfig.normalize_line_break_hyphens`、既定 ON）。 |
| 単文字数式変数の保護と補助警告 | 数式斜体フォントかつ斜体フラグを満たす、高確信度の独立した単文字変数（例: 本文中の `t`）を `{vN}` で保護します（`protect_isolated_math_vars`、既定 ON）。保護できなかった候補が訳文から消えた場合は、再試行やフォールバックを伴わない警告 `MATH_VARIABLE_MISSING` を記録します。 |

### 4 段階の検証履歴

`verification_stage` は、**その登録モデルに対する過去の検証実績**です。現在の接続状態ではありません。

| 段階 | 画面表示 | 意味 |
|---|---|---|
| `unverified` | 未検証 | 未検証、ファイル欠損、整合性エラー（利用不可） |
| `file_verified` | ファイル検証済み | SHA-256・GGUF 形式・互換性を確認済み |
| `launch_verified` | 起動確認済み | このアプリ経由で `llama-server` の起動を確認済み |
| `translation_verified` | 実翻訳確認済み | 実機推論が 1 ブロック以上完了した実績 |

`translation_verified` は機械による推論が完了したという実績です。**人間が訳文の品質を承認したことを意味しません。**
ファイルが欠損した間は `unverified`・利用不可となり、元の場所へ戻しても再検証が終わるまで実績は有効化されません。復元時の保持・リセット条件は [SPEC.md](SPEC.md) の 7.5 節を参照してください。

## 2. モデル別の位置づけ

| モデル | 位置づけ | 検証状況 |
|---|---|---|
| **PLaMo 3 Translate 2B（Q4_K_M）** | **既定・推奨**。 | 実機検証済み。 |
| **PLaMo 3 Translate 0.8B（Q4_K_M）** | 軽量な選択肢（約 0.57 GB）。 | 実ダウンロード・起動・翻訳を検証済み。ただし訳語の揺れや文脈依存の誤訳が残ります。 |
| **PLaMo 3 Translate 8B（Q4_K_M）** | カタログに収録（約 5.28 GB）。 | **今回の実機検証は未実施です。** 動作可能とも不可とも断定しません。大容量 VRAM または CPU モードの利用が案内されています。 |

- カタログ内の `catalog_verification_status` は、カタログに同梱されたメタデータ上の区分で、各登録モデルの検証履歴や今回の検証結果とは別です。0.8B と 8B は `catalog_verified_runtime_unverified` のままです。0.8B の実機検証結果は [VERIFICATION.md](VERIFICATION.md) に記録しています。
- PLaMo 3 Translate 31B は、サイズが大きいため対象外です。

## 3. 操作手順

### 3.1 新規ダウンロード

1. 初回セットアップ（`初回セットアップ.bat`）の確認画面で「導入するモデル」を選び、「公式 Hugging Face からダウンロードする」を選びます。セットアップを後回しにした場合や、あとからモデルを追加する場合は、アプリの画面1または画面4のモデル選択パネルから行います。
2. 表示されるライセンス告知（PLaMo コミュニティライセンス契約。公式条文は [日本語](https://plamo.preferredai.jp/info/plamo-community-license-ja) / [English](https://plamo.preferredai.jp/info/plamo-community-license-en)）を確認し、同意します（ダウンロードにはライセンスへの同意が必要です）。
3. ダウンロードが完了すると、サイズと SHA-256 が検証され、登録されます。「使用モデルにする」を有効にした場合は、そのまま選択状態になります。

### 3.2 既存 GGUF の reference 登録

1. セットアップ画面の「手元のダウンロード済み GGUF ファイルを SHA-256 検証して利用する」を選ぶか、アプリのモデル選択パネルでファイルを指定します。
2. 既定は reference 登録です（元のファイルをコピー・移動しません）。管理フォルダーへコピーしたい場合のみ、コピーのチェックを入れます。
3. ライセンス告知に同意すると、検証を経て登録されます。再ダウンロードは行いません。

登録したファイルを移動・削除すると、そのモデルは「未検証（ファイル欠損・要再指定）」となり使えなくなります。

### 3.3 使用モデルの選択

画面1または画面4のモデル選択パネルで、登録済みモデルから使用モデルを選びます。コマンドラインでは `scripts\model_setup.ps1 -Mode Select -ModelId <カタログID>` でも選択できます。

### 3.4 現在の接続・一致確認

モデル選択パネルの「現在の接続・一致」は、検証履歴とは別に次の状態を表示します。

| 表示 | 意味 |
|---|---|
| 接続可・一致 (`matched`) | 稼働中の `llama-server` が、選択モデルを読み込んでいることを確認できた。 |
| 接続可・同一モデル別パス (`matched_same_model_different_path`) | 同じモデルだが、読み込み元のパスが異なる。 |
| 接続可・パス未確認 (`server_path_unverified`) | 接続はできるが、パスを確認できなかった。 |
| 未確認 (`not_probed`) | まだ確認していない。 |
| 接続できない (`server_unreachable`) | 接続できなかった。**この表示だけでサーバーが停止していると断定するものではありません。** |
| 不一致 (`mismatch`) | 稼働中のサーバーが読み込んでいるモデルが、選択モデルと異なる。 |
| 選択モデル利用不可 (`selected_model_invalid`) | 選択中のモデルが無効、またはファイルが欠損している。 |
| モデル未選択 (`no_active_model`) | 使用モデルが選ばれていない。 |

### 3.5 不一致・接続不可のとき

- **不一致（`mismatch`）:** Web UI の選択は、起動済みの `llama-server` を入れ替えません。次のいずれかで、選択と稼働中サーバーを揃えてください。
  - 選択を、稼働中のサーバーが読み込んでいるモデルに戻す。
  - ランチャー（`起動する.bat` など）で起動した場合は、いったんアプリを終了してサーバーを停止し、使いたいモデルを選択した状態で、もう一度起動し直す想定です（ランチャーは起動時に選択中のモデルで `llama-server` を起動する設計ですが、同一ランチャーによるモデル切替・再起動の一連の動作は実機未検証です）。
  - 自分で別途 `llama-server` を起動している場合は、そのサーバーで目的のモデルを読み込み直す。接続先を変える場合は、環境変数 `PAPERBRIDGE_LLAMA_BASE_URL` を合わせる。
- **接続できない（`server_unreachable`）:** `llama-server` が起動していない、ポートや接続先設定が違う、などの可能性があります。接続先の表示と、画面4の疎通確認を確認してください。
- **選択モデル利用不可:** ファイルの場所を再指定するか、モデルを登録し直してください。

## 5. 既知の制約（要約）

詳細は [PUBLIC_LIMITATIONS.md](PUBLIC_LIMITATIONS.md) を参照してください。

- 8B は実機未検証です。
- 同一ランチャーによるモデル切替・再起動の一連の操作は未検証です。
- 単文字変数の保護は、数式斜体フォントかつ斜体フラグを満たすものに限ります。非 TeX 斜体、ローマン体で埋め込まれた変数、独立した `a` / `I`、演算子に隣接する変数などは対象外です。`a_t` のような添字付き変数など、既存の数式保護が対象外になるわけではありません。
- `MATH_VARIABLE_MISSING` には検出限界があります。判断できない場合は「照合不能」とし、「保持確認」とはしません。
- 0.8B と 2B のどちらも、訳語の揺れや誤訳が起こり得ます。出力 PDF は必ず目視で確認してください。
