# Public limitations

This initial release is a **Windows source-installed preview** of a local academic PDF translation tool. It is not a one-click installer, pre-built binary package, general PDF repair tool, OCR engine, or cloud translation service. Model weights (`PLaMo 3 Translate`), the inference server (`llama.cpp`), user documents, and local SQLite databases are not bundled; real translation requires running both this application and a separately obtained `llama-server` process.

- Scanned/image-only PDFs without an extractable text layer are not OCRed and are outside the supported path. Encrypted or corrupted PDFs may be rejected.
- Text within figures, complex tables, and other protected regions may remain untranslated. Complex inline formulas, references, or text that does not fit can produce warnings or fall back to original text; inspect the result rather than treating a completed job as proof of perfect preservation.
- Paragraphs that continue at column or selected-page boundaries receive neighboring masked text as context only when several structural, typographic, and textual signals agree. Blocks remain independently translated and drawn in their original boxes; this is not joined-sentence translation or a guarantee of coherent Japanese across boxes. Ambiguous candidates are recorded but not applied. The UI does not yet provide candidate accept/reject controls.
- The parser has no dedicated category for general footnotes. Paragraph classification and boundary signals cannot guarantee that every footnote pair is excluded; inspect candidate metadata and the output.
- In the inspected dual PDF, the reported English-labeled fraction equation is on physical PDF page 4 of 5, in the original panel's left column; a printed paper page number was not detected. Read-only parsing reproduced a classification/protection gap, and the parser now groups the label, numerator, denominator, equation number, and bar into one protected formula block. A synthetic visual regression reports zero differing pixels in its formula region while adjacent prose translates with a mock. A separate 2026-11-08 real-model run on a generated synthetic PDF also preserved its detected fraction region with zero differing pixels. Neither test replays the historical job: the provided document's exact model output and rendering behavior remain unknown. The `Eq. (n)` / `Equation (n)` reference pattern protects reference labels only; it is not the fraction-body fix. Restoring notation does not prove preservation of original glyphs or fonts.
- The input PDF is intended to remain unchanged; the application records and checks SHA-256. Keep a separate backup and verify outputs before relying on them.
- Python versions allowed by the project metadata are CPython 3.12 and 3.13 (`>=3.12,<3.14`). The recorded software/hardware configurations are examples, not minimum versions or requirements: a hardware-backed example is Windows 11 x64 with an AMD Radeon RX 7600 and Vulkan llama.cpp; a later same-PC synthetic test exercised CPU-only inference with PLaMo 3 Translate 2B GGUF Q4_K_M and four threads. This single CPU-only run does not establish general CPU compatibility or a minimum. The recorded frontend tooling includes Node.js 22.20.0 / npm 10.9.3, but the project does not declare a minimum Node.js/npm version. Minimum CPU, RAM, VRAM, and disk requirements remain undetermined, as does compatibility with other GPUs and operating systems.
- In the 2026-11-08 synthetic real-model trial at commit `6a55d6e31637f59f7b74b26d2d00efbc38977151`, the historical validation report attributed execution to a separate existing GPU server instead of the dedicated CPU inference endpoint. A subsequent 2026-11-08 fix matches local listeners by endpoint address and port, rejects ambiguous multi-PID or remote matches, and records actual compute backend as `unverified_from_api` alongside any verified local startup flags (`n_gpu_layers`) and `ggml-vulkan.dll` module state without claiming verified CPU or GPU execution from HTTP responses, missing DLLs, or startup flags alone. This fix was verified with deterministic mocks; the real-model trial was not rerun.
- A UI that opens without a model does not mean real translation is available. Screen 1 defaults to real-model inference (which transitions to `INTERRUPTED` if no inference server is running); deterministic mock trial mode must be explicitly selected on Screen 1 and is only for UI flow testing, not a translation-quality result. Real translation requires a separately obtained inference server and model.
- Browser access is restricted by default `allowed_origins` (`http://127.0.0.1:8080`, `http://localhost:8080`, `http://127.0.0.1:5173`, `http://localhost:5173`). Changing only Uvicorn's `--port` flag allows initial `GET` page loads, but browser `POST` / `PUT` / `DELETE` requests from other ports will be rejected with HTTP `403` unless `allowed_origins` is also aligned. Earlier isolated model-free checks on port `18081` verified HTTP `GET` reachability and home-screen display, not full interactive browser operations.
- The app's documented defaults use loopback for local services. Dependency installation/build and separate model acquisition may contact external distribution sites. Complete runtime network monitoring has not been established.
- The public preview repository name is `local-academic-pdf-translator-preview` (base project name: `local-academic-pdf-translator`). `PaperBridge Local` / `PaperBridge` remains in use as an internal provisional name across the UI, package metadata (`paperbridge-local`), environment variables (`PAPERBRIDGE_*`), runtime storage path (`%LOCALAPPDATA%\PaperBridgeLocal`), and auth header (`X-PaperBridge-Token`). Other unrelated projects named `PaperBridge` exist in the academic paper translation space, and neither name has been cleared for trademark or legal naming conflicts.

## Model terms and output obligations are separate

The app distributes source code only and does not bundle or redistribute the PLaMo model weights, derivative models, or translation outputs. The recorded model card revision is `232fbd7916519edecddfdae0beae7e76fe70453f`; both that revision and current `main` reference the PLaMo Community License Agreement (official URLs: [Japanese](https://plamo.preferredai.jp/info/plamo-community-license-ja) / [English](https://plamo.preferredai.jp/info/plamo-community-license-en), checked on 2026-11-08; initial check on 2026-11-07). The externally hosted license page is mutable, and the exact version of the full agreement text in force when the recorded revision was originally obtained cannot be verified from repository history alone. The model is not automatically covered by the project's AGPL license.

In the official PLaMo Community License Agreement checked on 2026-11-08:
- **Article 4 (Redistribution and Attribution Obligations / 第4条 再配布及び表示義務)** requires that when providing "the Model, etc. (including Derivative Models and their Outputs)" to a third party, the user must (i) provide a copy of the Agreement and require compliance, (ii) prominently display **`Built with PLaMo`** on related websites, user interfaces, blog posts, product pages, or product documentation, and (iii) include `PLaMo` in the name of any AI model created using the Model.
- **Article 5 (Use of Outputs / 第5条 生成物の利用)** requires that when publishing Outputs, the user must clearly indicate that the Outputs were generated by the Model or a Derivative Model, and states that models trained on Outputs are treated as Derivative Models under the Agreement.
- **In-app notice, unresolved scope, and verification targets:** The UI (Screen 1 and Screen 4) and project documentation display **`Built with PLaMo`**, the intended model (`PLaMo 3 Translate`), a statement that this tool is not an official Preferred Networks (PFN) product, notice that the application license (`AGPL-3.0-only`) and model license are separate, and click-only links to the official model repository and license pages (no automatic network requests are made at startup). However, the application does not automatically insert watermarks, origin attributions, or copies of the PLaMo license into generated PDFs. The developer has contacted the model provider while preparing this preview release, but does not claim individual official approval, unconditional availability, or absence of attribution obligations, and does not represent that the in-app or documentation notices alone satisfy every condition for all use cases (such as third-party sharing or publication of translated PDFs). Users must check the official license terms for their intended use.
